# TFIT — Design System

## Identity

Not a SaaS dashboard, not a "generated by AI" app. Reference quality bar: Apple Design, Nike Training Club, Strava, Whoop, Freeletics, Duolingo — for craft, motion, and retention mechanics only, never copied directly. TFIT's own identity:

- **Tone**: confident, calm, technical-but-warm. Sports performance, not gym-bro hype and not clinical/medical.
- **Avoid**: generic cards, heavy borders, gratuitous gradients, admin-dashboard density, repetitive components, walls of text, predictable grid layouts, floating decoration with no purpose, childish gamification skins.
- **Every animation has a job**: state change, causality (this action produced this result), or spatial continuity. No animation exists to "look modern."

## Tokens (`packages/ui/src/tokens`)

Token categories, defined once and consumed everywhere (mobile app; web admin reuses the same token values):

- `color` — semantic tokens (`color.background.base`, `color.text.primary`, `color.accent.primary`, `color.feedback.danger`, ...), each with a light and dark value. Components reference semantic tokens, never raw hex.
- `typography` — a type scale (display, title, headline, body, caption, label) with explicit line-height and weight, not ad hoc font sizes per screen.
- `space` — a spacing scale (4px base unit) used for all padding/margin/gap.
- `radius` — a small set of corner radii (sharp, soft, pill) used consistently by component role, not per screen.
- `elevation` — shadow/blur tokens for the few places depth is meaningful (modals, the workout-mode active card), not applied by default to every card.
- `motion` — duration/easing tokens (`motion.fast`, `motion.standard`, `motion.emphasis`) so animation feel is consistent app-wide, plus a `reducedMotion` variant respected everywhere.

## Theming

Dark mode is a first-class design, not an inverted palette: separate contrast/elevation decisions for dark surfaces (lower-saturation accents, deliberate elevation via subtle luminance steps rather than shadows, which don't read on dark backgrounds). Implemented via a `ThemeProvider` in `packages/ui` that resolves tokens from the OS color scheme with an explicit user override in `user_preferences`.

## Motion & 3D budget (master spec §28/§32)

- Reanimated for UI-thread microinteractions (set completion, XP gain, streak flame, level-up).
- Skia reserved for the exercise 3D/illustrative demonstrations (Phase 6) and trophy/badge rendering — never for routine list/card transitions.
- Every animated component ships a reduced-motion fallback and is profiled on a low-end Android target before merging (performance budget, not a suggestion).

## Screen state contract

Every screen must define, before implementation (master spec §57): loading, success, empty, error, and offline (where applicable) states. No screen ships with only the happy path.

## Navigation shape (master spec §49)

Bottom tab bar: `Home`, `Treinos`, `+` (center action: start workout / post / check-in), `Feed`, `Perfil`. Kept intentionally shallow — this is validated against real usage in Phase 5+ once social features add depth.

## Component philosophy

- Primitives (`Text`, `Surface`, `Button`, `Stack`) in `packages/ui/src/primitives`, token-driven, no screen-specific styling leaking in.
- Composed components (`WorkoutCard`, `XPBar`, `StreakBadge`, ...) are built from primitives, added when the screen that needs them is actually built — not speculatively.
