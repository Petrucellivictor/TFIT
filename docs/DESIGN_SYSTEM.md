# TFIT — Design System

## Identity — "Performance Tech" (revised)

Not a SaaS dashboard, not a "generated by AI" app. Reference quality bar: Apple Design, Nike Training Club, Strava, Whoop, Oura, Freeletics — for craft, motion, and retention mechanics only, never copied directly. The identity was deliberately pushed further at the user's explicit request for something "mais elaborada, tecnológica, que remeta a saúde ou academias" (more elaborate, technological, evoking health/gyms) — a real revision, not additive decoration:

- **Tone**: confident, data-forward, premium-tech. Sports performance and biometric-wearable energy (Whoop/Oura-style dark UI), not gym-bro hype and not clinical/medical.
- **Dark is the flagship surface**, not a toggle-able alternative: deep near-black backgrounds (`#060A10`) with a vivid electric mint→blue gradient accent (`#1EF2A6` → `#3DB2FF`) used deliberately for CTAs, data visualization, and glow accents — this reverses the earlier "avoid gratuitous gradients" stance now that the brief explicitly calls for a more elaborate/technological feel. Gradients and glow shadows are used with intent (primary actions, score/progress displays, unlocked-achievement rings), not on every surface.
- **Every animation has a job**: state change, causality (this action produced this result), or spatial continuity. No animation exists to "look modern."

## Tokens (`packages/ui/src/tokens`)

Token categories, defined once and consumed everywhere (mobile app; web admin does not consume `@tfit/ui` — it's a plain Next.js app with its own minimal inline styling, see `apps/admin/src/app/globals.css`):

- `color` — semantic tokens (`color.background.base`, `color.text.primary`, `color.accent.primary`, `color.accent.secondary`, `color.feedback.danger`, `color.gradient.primary`/`color.gradient.hero`, ...), each with a light and dark value. Components reference semantic tokens, never raw hex. `gradient.primary` is the `[accent.primary, accent.secondary]` pair used by `Button`'s primary variant, `ScoreBar`'s fill, the FAB, and `RadialGauge`'s ring — one token pair, applied consistently, rather than each component picking its own gradient.
- `typography` — a type scale (display, title, headline, body, caption, label) with explicit line-height and weight, not ad hoc font sizes per screen.
- `space` — a spacing scale (4px base unit) used for all padding/margin/gap.
- `radius` — a small set of corner radii (sharp, soft, pill) used consistently by component role, not per screen.
- `elevation` — implemented via `Surface`'s `glow` prop (accent-tinted shadow, reserved for hero/highlight cards — the gamification summary, the FIT Score card) and `Button`'s primary-variant shadow, not applied by default to every card.
- `motion` — duration/easing tokens (`motion.fast`, `motion.standard`, `motion.emphasis`) so animation feel is consistent app-wide, plus a `reducedMotion` variant respected everywhere.

## Theming

Dark mode is a first-class design, not an inverted palette: separate contrast/elevation decisions for dark surfaces (lower-saturation accents, deliberate elevation via subtle luminance steps rather than shadows, which don't read on dark backgrounds). Implemented via a `ThemeProvider` in `packages/ui` that resolves tokens from the OS color scheme with an explicit user override in `user_preferences`.

## Motion & 3D budget (master spec §28/§32)

- Reanimated for UI-thread microinteractions (set completion, XP gain, streak flame, level-up, like-button burst) — implemented in Phase 7 for the rest timer, XP/FIT Score bars, achievement unlock celebration, and badge entrance animation.
- `react-native-svg` (+ Reanimated's `useAnimatedProps`) for circular/vector data-viz — the rest-timer ring (Phase 7) and its generalization, `RadialGauge` (a reusable gradient-stroke ring for any 0-100 score: level progress on Home, FIT Score on Evolution), rather than pulling in Skia. Skia stays reserved for actual exercise 3D/illustrative demonstrations, which remain deferred pending real content and an admin content-upload pipeline (neither exists — Phase 9's admin panel shipped only a reports queue, docs/ARCHITECTURE.md); no placeholder 3D work was built to fill a phase number.
- `expo-linear-gradient` for rectangular/pill gradient fills (buttons, the FAB, hero header backgrounds, achievement-badge rings) — `react-native-svg`'s gradients are used specifically for the circular gauges since that's SVG-native; `expo-linear-gradient` is the simpler, correct tool for gradient `View` backgrounds and doesn't require hand-rolling `<Rect>` shapes.
- Every animated component ships a reduced-motion fallback and is profiled on a low-end Android target before merging (performance budget, not a suggestion). The Phase 7 components (rest-timer ring, progress bars, achievement entrance, celebration modal, like-button burst) all check `theme.reducedMotion` and snap instead of animating when it's on.

## Accessibility (Phase 9)

Every icon-only or ambiguous-purpose `Pressable` app-wide carries `accessibilityRole="button"` and a Portuguese `accessibilityLabel` — modal close buttons, like/comment/menu icons, reorder chevrons, state toggles (labels reflect current state, e.g. "Curtir"/"Descurtir"). `Pressable`s wrapping already-self-descriptive visible text (a `Button` labeled "Salvar", a settings row whose own text names the destination) are deliberately left as-is — mechanically labeling everything would be noise for a screen reader, not help. Minimum touch targets get `hitSlop={8}` where an icon's hit area would otherwise fall under ~44 logical pixels. Not yet audited: color contrast ratios against WCAG AA (the token palette was designed by eye, not measured) and screen-reader flow-order testing on a real device — both worth a dedicated pass, not folded into this one.

## Screen state contract

Every screen must define, before implementation (master spec §57): loading, success, empty, error, and offline (where applicable) states. No screen ships with only the happy path.

## Navigation shape (master spec §49)

Bottom tab bar: `Home`, `Treinos`, `Personal`, `Feed`, `Perfil`, plus a floating `+` action button overlaid on the bar (start workout / check-in / post) rather than consuming a tab slot. `Personal` (the trainer directory, Phase 5) was added to the original 4-tab plan at the user's request; `Feed` (Phase 6, social) fit into the existing 5th slot without needing a 6th tab. 5 tabs plus an overlaid FAB is still within normal mobile bottom-nav bounds.

## Component philosophy

- Primitives (`Text`, `Surface`, `Button`, `Stack`) in `packages/ui/src/primitives`, token-driven, no screen-specific styling leaking in. `Surface` and `Button` gained `glow`/gradient treatments in the Performance Tech revision — still primitives (no screen-specific logic), just with a richer visual vocabulary than the original flat-fill design.
- Composed components (`ScoreBar`, `RadialGauge`, `CircularTimer`, ...) live app-side in `apps/mobile/src/components`, built from primitives, added when the screen that needs them is actually built — not speculatively.
